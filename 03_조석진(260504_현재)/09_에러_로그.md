# 9. 에러 처리 및 로그 정책 (Error Logging)

## 1. 에러 처리 체계

### iOS (`APIError`)
커스텀 열거형을 사용하여 네트워크 및 데이터 에러를 분류합니다.
- `invalidURL`: 잘못된 엔드포인트.
- `requestFailed`: 네트워크 요청 실패.
- `invalidResponse`: 비정상적인 서버 응답.
- `decodingFailed`: JSON 파싱 에러.
- `httpError(statusCode, message)`: HTTP 상태 코드별 에러 (404 등).

### Android
- **Retrofit Callback:** 응답 코드에 따른 분기 처리 (`isSuccessful` 여부 확인).
- **Result Wrapper:** `Result<T>` 패턴을 사용하여 도메인 레이어로 에러 전달.

## 2. 로그 정책

### 개발 단계
- **iOS:** `print()` 및 `debugPrint()`를 사용하여 콘솔 로그 출력.
- **Android:** `Log.d`, `Log.e` (Timber 미사용 확인, 표준 Log 클래스 사용).

### 운영 단계 (미지원)
- 현재 Crashlytics 또는 Sentry와 같은 외부 로그 수집 도구의 구현은 확인되지 않음 (향후 추가 필요).
