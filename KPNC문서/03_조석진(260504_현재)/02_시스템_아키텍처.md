# 2. 시스템 아키텍처 (System Architecture)

## 전체 구조도
본 프로젝트는 모바일 앱(iOS/Android)이 각 플랫폼의 건강 데이터 스토어(HealthKit/Health Connect)로부터 데이터를 수집하고, 이를 가공하여 중앙 연구 서버(REST API)로 전송하는 구조를 가집니다.

## 앱 레이어 구조

### iOS (MVVM + Repository)
- **Presentation:** SwiftUI View 및 ViewModel. UI 상태 관리 및 사용자 상호작용 처리.
- **Domain:** 비즈니스 로직 및 모델 정의. Repository 인터페이스 포함.
- **Data:** Repository 구현체, API 클라이언트, HealthKit 데이터 소스.
- **Core:** 네트워크 설정, 보안(Keychain), 유틸리티.

### Android (Clean Architecture)
- **Presentation:** Jetpack Compose 스크린 및 ViewModel.
- **Domain:** 엔티티(Entity), Repository 인터페이스, UseCase.
- **Data:** 데이터 소스(Local/Remote), Repository 구현체, 매퍼(Mapper).
- **DI (Hilt):** 의존성 주입을 통한 레이어 간 결합도 완화.

## 데이터 흐름
1. **데이터 수집:** 플랫폼 서비스(HealthKit/Health Connect)가 백그라운드 또는 포그라운드에서 데이터를 조회.
2. **로컬 요약:** 수집된 원시 데이터를 일별 요약 모델(`DailyHealthData`)로 변환.
3. **서버 전송:** `APIClient`를 통해 연구 서버의 `/health/sync.do` 엔드포인트로 JSON 데이터 전송.
4. **결과 처리:** 서버 응답에 따라 로컬 동기화 상태 업데이트.

## 상태 관리 방식
- **iOS:** `@StateObject`, `@Published`를 사용한 Observable 객체 기반 상태 관리.
- **Android:** `StateFlow` 및 Compose `State`를 활용한 단방향 데이터 흐름(UDF).

## 네트워크 구조
- **공통 Base URL:** `https://kpnc.chemainet.com/vest2025`
- **인증 방식:** Bearer Token 기반 Authorization 헤더 사용.
- **통신 라이브러리:**
  - iOS: `URLSession` 기반 커스텀 `APIClient`.
  - Android: `Retrofit2` 및 `OkHttp3` 인터셉터 활용.
